# f-42: `kley install` defaults to `link:` protocol

- **Milestone:** M2
- **Complexity:** Medium
- **Depends On:** f-41

## 1. Problem Statement

`kley install` is the high-level "do it for me" command: it should leave the
user with a working dependency and automatic propagation on
`publish --push` / `watch`. Today it results in a `file:` specifier (the
package manager writes `file:.kley/<pkg>` when given a local path), so
`node_modules/<pkg>` may be a **copy** — and after `publish --push` only
`.kley/<pkg>` is refreshed, leaving `node_modules` stale in copy-mode.

Semantically `kley install` should equal `kley add --link` + `npm install`:
write `link:.kley/<pkg>` so the PM symlinks `node_modules/<pkg> → .kley/<pkg>`,
and push/watch propagate automatically regardless of npm's `install-links`
config.

## 2. Proposed Solution

Change `kley install` to inject a `link:` specifier into `package.json` (reuse
the injection added in `f-41`) and then run the package manager. `kley add`
stays `file:` by default (manual approach).

`node_modules/<pkg>` becomes a symlink to `.kley/<pkg>`, so `publish --push`
and `watch` propagate changes without extra steps. The singleton/peer-dep risk
is neutralized because `.kley/` lives inside the project root.

## 3. Implementation Plan

1. In `install_package` (`src/commands/install.rs`), instead of letting the PM
   write `file:` (passing the local path), write `link:.kley/<pkg>` into
   `package.json` via `PackageJson::update_dependency` (link mode from `f-41`),
   then run the PM install.
2. Preserve `--no-save`, `--dev` semantics.
3. Keep `kley add` defaulting to `file:`.
4. Ensure backward compatibility: existing `file:` setups still install
   correctly (the fast-path in `install.rs` already handles symlink/copy
   destinations).

## 4. Usage Examples

```bash
kley install my-lib
# package.json: "my-lib": "link:.kley/my-lib"
# node_modules/my-lib -> .kley/my-lib (symlink)
# after `kley publish --push`: changes appear immediately
```

## 5. Acceptance Criteria

- `kley install <pkg>` writes a `link:` specifier into `package.json` and the
  PM symlinks `node_modules/<pkg> → .kley/<pkg>`.
- `publish --push` / `watch` propagate to `node_modules` without re-running
  install (in default npm/pnpm/yarn configs).
- `kley add` still defaults to `file:`.
- Existing `file:`-based setups remain functional.
- Documented in `README.md` and `docs/feature-parity-kley-vs-yalc.md`.
