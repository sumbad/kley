# f-45: `--quiet` / `--no-colors` output control

- **Milestone:** M2
- **Complexity:** Low
- **Depends On:** None

## 1. Problem Statement

kley only supports increasing verbosity (`-v`/`--verbose`). There is no way to
silence non-error output for scripts/CI, nor to disable ANSI colors when the
terminal or log collector doesn't support them.

yalc provides `--quiet` and `--no-colors`.

## 2. Proposed Solution

Add two global flags:
- `--quiet`: suppress all non-error output (still print errors/warnings).
- `--no-colors`: disable colored output (the `colored` crate usage).

## 3. Implementation Plan

1. Add `--quiet` and `--no-colors` to `Cli` in `src/main.rs`.
2. Route `println!`/status output through a helper that respects `--quiet`.
3. Gate `colored` styling on `!no_colors` (or set a global "colors enabled"
   flag read by the styling helpers).
4. Keep `-v` for verbose as-is.

## 4. Usage Examples

```bash
kley publish --push --quiet
kley install my-lib --no-colors
```

## 5. Acceptance Criteria

- `--quiet` suppresses non-error output.
- `--no-colors` removes ANSI color codes from output.
- Existing verbose behavior unchanged.
- Documented in `README.md`.
