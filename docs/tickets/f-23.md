# f-23: Publish Hooks (`.kley/hooks.json` + wizard)

- **Milestone:** M2
- **Complexity:** High
- **Depends On:** None (reuses existing `kley publish`)
- **Spec:** [`docs/kley-publish-hooks-spec.md`](../../kley-publish-hooks-spec.md)

## 1. Problem Statement

`kley publish` is, by design, a pure file-copy into the local store — it never
executes any `package.json` lifecycle script. This is a deliberate,
security-conscious departure from `yalc`, where implicit execution of
`prepublish`/`prepare`/`prepack`/`publish`/`postpublish` can accidentally trigger
a real publish to the npm registry (see
[yalc#255](https://github.com/wclr/yalc/issues/255)).

The downside: many packages (especially TypeScript) keep their build step in
`prepublishOnly`/`prepack`/`prepare`. With no hook support, the user must build
manually before every `kley publish`.

## 2. Proposed Solution

An explicit, user-controlled set of hooks stored **separately** from
`package.json` — in `.kley/hooks.json` at the package root. Kley **never** reads
`scripts` from `package.json` at publish runtime — only from this file. The file
is populated through an interactive wizard on first publish.

Full design, file format, flow, wizard and CLI flags are specified in
[`docs/kley-publish-hooks-spec.md`](../../kley-publish-hooks-spec.md). This ticket
tracks implementation and the two mandatory fixes below.

### Commands

```bash
kley publish                    # flow: wizard (first run) → pre hooks → copy → post hooks
kley publish --non-interactive  # no wizard; hooks run only if .kley/hooks.json exists
kley publish --no-hooks         # ignore .kley/hooks.json this run, pure copy
kley hooks list                 # show current .kley/hooks.json, readable
kley hooks edit                 # re-run wizard, rebuild .kley/hooks.json
```

### Module layout

- `src/hooks/registry.rs` — `HookPhase` (Pre/Post), `KNOWN_HOOKS`, `HookEntry`,
  `HooksConfig` (serde flatten `HashMap`), `load()`/`save()`.
- `src/hooks/wizard.rs` — `run_hooks_wizard(ctx, path)` via `dialoguer`
  multiselect over `package.json.scripts ∩ KNOWN_HOOKS`; always writes the file
  (even `{}`, which is the "wizard already ran" marker).
- `src/hooks/runner.rs` — `run_phase(config, phase, ctx)` executes commands via
  `std::process::Command`; aborts on non-zero exit (pre failure → copy not
  called; post failure → files already copied but command still errors).
- `src/commands/hooks.rs` — `list` and `edit`.

### Mandatory fix #1 — `.kley/` must be excluded from publish

`publish` currently ignores `.git`, `node_modules`, lockfiles and `.npmrc`
(`src/commands/publish.rs`), but **not** `.kley/`. A library that also consumes
local packages would otherwise bundle its own `.kley/` (incl. `hooks.json`) into
the store. Add `!.kley/` to the `OverrideBuilder` ignore list.

### Mandatory fix #2 — `kley hooks edit` must preserve manual entries

The wizard derives candidates only from `package.json.scripts`. `kley hooks edit`
must use **merge semantics**: existing `.kley/hooks.json` entries that are not
present in `package.json` are kept (used as default checkbox state and never
dropped on rewrite).

### Dependencies

Add `dialoguer` to `Cargo.toml` for the multiselect TUI.

## 3. Acceptance Criteria

- `kley publish` never reads `package.json` `scripts` at runtime; only
  `.kley/hooks.json`.
- First `kley publish` (no file, interactive) runs the wizard, writes
  `.kley/hooks.json` (possibly `{}`), and proceeds.
- Existence of `.kley/hooks.json` (even empty) suppresses the wizard on later
  runs.
- `--non-interactive` with no file → pure copy, no wizard. `--no-hooks` ignores
  an existing file for that run.
- Pre hooks run before file copy; post hooks after. Any hook failure aborts
  `kley publish` with a non-zero exit; a failing pre hook leaves no files copied.
- `kley hooks list` prints the current config readably.
- `kley hooks edit` rebuilds the config without dropping manual hooks absent from
  `package.json`.
- `.kley/` is excluded from published package content.
- Unit tests: `KNOWN_HOOKS` phase mapping, `HooksConfig` load/save roundtrip
  (incl. empty `{}`), runner success/failure. Integration tests: publish with
  pre-existing hooks.json executes the hook; `--no-hooks` overrides; pre-hook
  failure aborts; `hooks edit` preserves manual entries.
- `README.md` documents the hook flow, flags, `kley hooks list/edit`, and a
  warning that hooks come only from `.kley/hooks.json`.
