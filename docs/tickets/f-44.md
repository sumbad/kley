# f-44: `--store-folder` flag

- **Milestone:** M2
- **Complexity:** Low
- **Depends On:** None

## 1. Problem Statement

The store location can only be overridden via the `KLEY_HOME` environment
variable. There is no per-invocation flag, which is inconvenient for CI jobs
or one-off commands that need an isolated store.

yalc provides `--store-folder`.

## 2. Proposed Solution

Add a global `--store-folder <path>` flag that overrides the store directory
for the command (equivalent to `KLEY_HOME` for that invocation). It should take
precedence over `KLEY_HOME`.

## 3. Implementation Plan

1. Add `--store-folder` to the `Cli` struct in `src/main.rs`.
2. Pass it through `Registry::new` (which already accepts a home dir) so all
   commands use the overridden store.
3. `KLEY_HOME` remains as the env fallback; flag wins.

## 4. Usage Examples

```bash
kley --store-folder /tmp/ci-store publish
kley --store-folder /tmp/ci-store install my-lib
```

## 5. Acceptance Criteria

- `--store-folder <path>` changes the store location for the command.
- Flag overrides `KLEY_HOME`; without it, existing behavior is unchanged.
- Documented in `README.md`.
