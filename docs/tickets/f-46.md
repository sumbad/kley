# f-46: `publish --content` (preview packaged files)

- **Milestone:** M2
- **Complexity:** Low
- **Depends On:** None

## 1. Problem Statement

There is no way to preview which files will be included in the published
package before actually writing to the store. This makes it hard to verify
`.npmignore`/`.kleyignore`/`files` rules.

yalc provides `yalc publish --content`.

## 2. Proposed Solution

Add `kley publish --content` that runs the same file-collection/filtering logic
as a real publish but only **prints the list** of files that would be copied,
without writing to the store.

## 3. Implementation Plan

1. Factor the file-walk/filter logic in `src/commands/publish.rs` into a
   function that returns the list of included relative paths.
2. On `--content`, call it and print the list; skip copying/hooks/registry
   writes.
3. Without `--content` behavior is unchanged.

## 4. Usage Examples

```bash
kley publish --content
# prints:
#   package.json
#   dist/bundle.js
#   README.md
```

## 5. Acceptance Criteria

- `kley publish --content` lists the files that would be published.
- It does not modify the store or `package.json`.
- Filtering matches a real publish (`.npmignore`/`.kleyignore`/`files`).
- Documented in `README.md`.
