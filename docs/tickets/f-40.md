# f-40: Add `add --workspace` / `-W` flag

- **Milestone:** M2
- **Complexity:** Low
- **Depends On:** f-39

## 1. Problem Statement

In a workspaces project, users want kley to inject a `workspace:`-protocol
dependency into `package.json` (so the workspace manager resolves the local
package) instead of the default `file:` specifier. yalc supports this via
`yalc add <pkg> --workspace` (`-W`).

kley `add` today only writes `file:.kley/<pkg>`.

## 2. Proposed Solution

Add `--workspace`/`-W` to `kley add`. When set, `PackageJson::update_dependency`
writes a `workspace:` specifier (e.g. `"my-lib": "workspace:^1.0.0"` or
`"workspace:*"`) instead of `file:`.

Requires `f-39` so the resolved version is available for the `workspace:`
range.

## 3. Implementation Plan

1. Add `workspace: bool` to the `Add` variant in `src/main.rs`.
2. Pass it into `commands::add::add(...)`.
3. Extend `PackageJson::update_dependency` with a mode that emits a
   `workspace:` specifier using the resolved version from `f-39`.
4. Leave `kley add` (no flag) writing `file:` as before.

## 4. Usage Examples

```bash
kley add my-lib --workspace     # "my-lib": "workspace:^1.0.0" in package.json
kley add my-lib -W              # same, short form
```

## 5. Acceptance Criteria

- `kley add <pkg> --workspace` writes a `workspace:` specifier into
  `package.json`; `kley add <pkg>` still writes `file:`.
- Works only when the resolved version is known (depends on `f-39`).
- Backward compatible; documented in `README.md`.
