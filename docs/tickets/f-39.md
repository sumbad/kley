# f-39: Resolve `workspace:` protocol in dependencies

- **Milestone:** M2
- **Complexity:** Low
- **Depends On:** None

## 1. Problem Statement

In Yarn/Pnpm/npm workspaces a package's own `dependencies`/`peerDependencies`
may use the `workspace:` protocol (e.g. `"react": "workspace:^18.0.0"`). When
such a package is published/added via kley, the `workspace:` specifier is left
unresolved, so the consuming project either fails to install or ends up with a
broken `workspace:` reference pointing nowhere.

yalc resolves `workspace:` by default (opt-out via `--no-workspace-resolve`).
kley currently does nothing with it.

## 2. Proposed Solution

When reading a package's dependencies during `publish`/`add`, detect values
starting with `workspace:` and resolve them to the concrete local version
(semver range preserved, protocol stripped). The resolved child gets its own
entry in `kley.lock`, and the parent's lock entry records the same stripped
range (snapshotted from the installed copy under `.kley/`, see §6).

Add a global/per-command flag `--no-workspace-resolve` to disable resolution
and keep the raw `workspace:` specifier (mirrors yalc).

## 3. Implementation Plan

1. In `src/package.rs` (dependency parsing), add a helper that, given a
   dependency spec, returns the resolved version when the spec starts with
   `workspace:`.
2. During `publish` (`src/commands/publish.rs`) and `add`, resolve
   `workspace:` deps before copying/recording; store the resolved version in
   the registry and give the resolved child its own entry in `kley.lock`. The
   parent's lock entry records the stripped range from the installed copy.
3. Add `--no-workspace-resolve` flag (default off) that skips resolution.
4. Keep behavior backward compatible: packages without `workspace:` deps are
   unaffected.

## 4. Usage Examples

```bash
kley publish                 # workspace: deps resolved automatically
kley publish --no-workspace-resolve   # keep raw workspace: specifiers
```

## 5. Acceptance Criteria

- `workspace:` specifiers in a published package's dependencies are resolved to
  concrete versions; the resolved child is recorded in `kley.lock`, and the
  parent's lock entry records the same stripped range.
- `--no-workspace-resolve` preserves the raw `workspace:` specifier.
- Packages without `workspace:` deps behave exactly as before.
- Documented in `README.md` and referenced from
  `docs/feature-parity-kley-vs-yalc.md`.

## 6. Finalized Implementation Plan

1. **Mental model:** a `workspace:` dependency is equivalent to running
   `kley add <dep>` for that dependency. So in code we literally install the
   referenced package into the project (copy into `.kley/`, record the
   installation) and rewrite the `workspace:` specifier.
2. **`workspace:` is always stripped** to a plain semver range
   (`my-lib: "workspace:^1.2.0"` → `my-lib: "^1.2.0"`) — both in normal and
   `--pure` mode. The only mode-dependent part is whether the resolved dep is
   also injected as `file:.kley/<dep>` into the project's root `package.json`
   (skipped in `--pure`, matching f-38).
3. **Transitive resolution** with a cycle guard (a `visited` set threaded
   through `run_update`).
4. **Range check:** if the referenced package is absent from the kley
   registry, or its single stored version does not satisfy the `workspace:`
   range, resolution is skipped — the specifier is still stripped to a plain
   range (as in `--pure`) and a warning is printed. No local `file:` link is
   created in that case.
5. **kley.lock stays deterministic:** `update_kley_lock` reads the installed
   copy under `.kley/<pkg>` (which `run_update` has already stripped of the
   `workspace:` prefix), so the parent's lock entry records the stripped plain
   range — not the raw `workspace:` specifier. The resolved child gets its own
   entry too, and `install_package` compares the lock against that same
   installed copy, so the two are always in sync. No deferred work remains for
   this (see `src/commands/update.rs`).

### Where resolution happens
At **install/add/update/push time**, inside `run_update`
(`src/commands/update.rs`), after `copy_from_registry` +
`strip_dev_dependencies` — NOT at `publish` (the store copy stays the portable
`workspace:` source of truth). `run_update` is the single funnel called by
`add`, `update`, `publish --push` and `install`.

### Changes
- `Cargo.toml`: add `semver = "1"`.
- `src/package.rs`: `extract_and_strip_workspace_protocol(dir)` — finds
  `workspace:` in `dependencies` (injectable) and `peerDependencies`
  (strip-only), rewrites them to plain ranges, returns the extracted deps.
- `src/commands/update.rs`: `run_update` gains `pure`, `resolve_workspace` and
  `visited: &mut HashSet<String>`; new `resolve_workspace_links` does the
  strip + per-dep `install_package_into_project` (recursive, cycle-guarded).
- `src/commands/add.rs`: extract `install_package_into_project` (copy +
  optional `file:.kley` injection + record installation) shared by `add` and
  workspace resolution; `add` keeps CLI behavior.
- `src/main.rs`: `--no-workspace-resolve` on `Add`, `Install`, `Update`,
  `Publish`; threaded through to `run_update`.
- Tests: unit for `extract_and_strip_workspace_protocol`; integration for
  `kley add` of a package with a `workspace:` dep (child copied, root injected,
  internal specifier stripped; `--no-workspace-resolve` keeps raw; absent dep
  warns).
