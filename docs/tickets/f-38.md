# f-38: Add `--pure` flag to `add` (workspaces support)

- **Milestone:** M2
- **Complexity:** Low
- **Depends On:** None

## 1. Problem Statement

In Yarn/Pnpm/npm **workspaces** the package manager owns linking between
packages via the `workspaces` globs in `package.json`. When a user runs
`kley add <pkg>` today, kley injects a `file:.kley/<pkg>` dependency into
`package.json` (`src/commands/add.rs:21`). That pollutes `package.json` and
conflicts with the workspace manager, which expects to link `.kley/*` itself
after `yarn install`.

Note: `kley add` already does **not** touch `node_modules` — it only copies to
`.kley/`, updates `package.json` + `kley.lock`, and tells the user to run
`npm install`. So the gap is specifically the `package.json` mutation, not
`node_modules`.

yalc solves this with `yalc add --pure` (and makes it the default inside
workspaces): copy to `.yalc/`, register the package, but touch **neither**
`package.json` nor `node_modules`. kley has no equivalent mode.

## 2. Proposed Solution

Add a `--pure` flag to `kley add`:

- Copies the package into `.kley/` (via `run_update`, `src/commands/update.rs:76`).
- Registers the installation in `kley.lock` (`registry.add_package_installation`,
  `src/commands/add.rs:23`) **so `publish --push` can still find and update the
  project**.
- Does **not** call `PackageJson::update_dependency` — `package.json` is left
  untouched.
- Does **not** touch `node_modules` (unchanged from current `add` behavior).

### Default behavior in workspaces

When kley detects a `workspaces` field in the project's `package.json`, treat
`--pure` as the default (mirroring yalc). Allow opting out with `--no-pure`.

```bash
kley add my-lib --pure          # don't touch package.json / node_modules
kley add my-lib                 # in a workspace project → pure by default
kley add my-lib --no-pure       # force the normal file: injection
```

This is distinct from `kley install --no-save`, which skips `package.json` but
**does** install into `node_modules`. `--pure` skips both.

## 3. Implementation Plan

1. Add `pure: bool` to the `Add` variant in `src/main.rs` (`--pure` long flag).
2. Pass `pure` into `commands::add::add(...)`.
3. In `add()`, guard the `PackageJson::update_dependency` call:
   ```rust
   if !pure {
       PackageJson::update_dependency(&dirs.project_dir, package_name, is_dev)?;
   }
   ```
   `run_update` and `add_package_installation` stay unconditional so push works.
4. Detect workspaces: when parsing the project `package.json`, if a `workspaces`
   key exists and `--no-pure` was not passed, set `pure = true` by default.
5. Add a short note in output when `--pure` is active, e.g.
   `"Note: package.json and node_modules left untouched (--pure)."`

## 4. Usage Examples

```bash
# Workspace project (package.json has "workspaces": ["packages/*"])
kley add shared-ui
# → copies to .kley/shared-ui, records in kley.lock, package.json untouched
# user adds ".kley/*" to workspaces and runs `yarn install`

# Non-workspace project, explicit pure
kley add shared-ui --pure

# Opt out inside a workspace
kley add shared-ui --no-pure   # injects file: dependency as usual
```

## 5. Acceptance Criteria

- `kley add <pkg> --pure` copies to `.kley/` and updates `kley.lock` but does
  **not** modify `package.json` or `node_modules`.
- With `--pure`, `kley publish --push` from the library still updates the
  project (installation is recorded in `kley.lock`).
- Inside a project that declares `workspaces`, `kley add <pkg>` behaves as
  `--pure` by default; `--no-pure` restores the `file:` injection.
- Outside a workspace, default behavior is unchanged (backward compatible).
- `--pure` is documented in `README.md` and the workspaces comparison in
  `docs/feature-parity-kley-vs-yalc.md` is updated.
