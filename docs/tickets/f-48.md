# f-48: `publish <sub-project>` (monorepo publish)

- **Milestone:** M2
- **Complexity:** Low
- **Depends On:** None

## 1. Problem Statement

`kley publish` only works from the package's own directory (cwd). In a monorepo
with multiple sub-packages it is convenient to publish a sub-project by path
without `cd`-ing into it.

yalc supports `yalc publish some-project` (relative sub-directory).

## 2. Proposed Solution

Allow `kley publish [path]` where `path` is a sub-directory containing a
package. kley changes into that directory (or resolves its `package.json`) for
the publish, then returns. Combine with `--push` as usual.

## 3. Implementation Plan

1. Make the `Publish` command accept an optional `path` argument.
2. When provided, resolve the package root from `path` (find `package.json`)
   and run the publish logic there instead of cwd.
3. Keep `kley publish` (no path) behaving exactly as today.

## 4. Usage Examples

```bash
kley publish packages/my-lib          # publish sub-project
kley publish packages/my-lib --push   # publish + push installations
```

## 5. Acceptance Criteria

- `kley publish <path>` publishes the package at that path.
- `kley publish` (no path) unchanged.
- `--push` works with a sub-project path.
- Documented in `README.md`.
