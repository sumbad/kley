# f-43: `--sig` content hash version signature

- **Milestone:** M2
- **Complexity:** Low
- **Depends On:** None

## 1. Problem Statement

During local development the package's semver (e.g. `1.2.3`) is rarely bumped
between edits, so repeated `publish` calls all record the same version in
`kley.lock`. There is no way to tell which content snapshot is actually
installed, and package managers may skip reinstall because the version string
is unchanged.

yalc solves this with `--sig`, appending a content hash to the version
(`1.2.3+ffffffff`).

## 2. Proposed Solution

Add `kley publish --sig`. When set, compute a hash of the packaged file
contents and append it to the version (`1.2.3+<hash>`). The hashed version is
stored in the registry and recorded in `kley.lock`. Off by default.

This also complements `f-22` (`push --changed`): the same content hash is used
to decide whether to push and to force a PM reinstall via the changed version
string.

## 3. Implementation Plan

1. In `publish` (`src/commands/publish.rs`), after collecting packaged files,
   compute a stable hash (e.g. over sorted file paths + contents).
2. Append `+<hash>` to the version used for the registry entry and `kley.lock`.
3. Add `--sig` flag (default off) and a `.kleyrc` setting `sig` (see `f-24`).
4. Without `--sig` behavior is unchanged.

## 4. Usage Examples

```bash
kley publish --sig     # version recorded as 1.2.3+a1b2c3
```

## 5. Acceptance Criteria

- `kley publish --sig` records a version with a content-hash suffix.
- Without `--sig` the version is unchanged (backward compatible).
- The hash is deterministic for identical content.
- Documented in `README.md`.
