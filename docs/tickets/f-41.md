# f-41: Add `add --link` flag (manual `link:` injection)

- **Milestone:** M2
- **Complexity:** Low
- **Depends On:** None

## 1. Problem Statement

`kley add` is the low-level, manual command: it writes `file:.kley/<pkg>` into
`package.json` and leaves the actual install to the user (`npm install`). Some
users want manual control to inject a `link:` specifier instead of `file:`
without switching to the higher-level `kley install`.

yalc provides this via `yalc add <pkg> --link`.

## 2. Proposed Solution

Add `--link` to `kley add`. When set, `PackageJson::update_dependency` writes
`link:.kley/<pkg>` into `package.json` instead of `file:`. `kley add` without
the flag keeps writing `file:` (manual approach unchanged).

This is the manual counterpart to `f-42` (where `kley install` defaults to
`link:`).

## 3. Implementation Plan

1. Add `link: bool` to the `Add` variant in `src/main.rs`.
2. Pass it into `commands::add::add(...)`.
3. Extend `PackageJson::update_dependency` with a `link:` mode that emits
   `link:.kley/<pkg>`.
4. `kley add` (no flag) continues to write `file:`.

## 4. Usage Examples

```bash
kley add my-lib            # "my-lib": "file:.kley/my-lib"  (manual)
kley add my-lib --link     # "my-lib": "link:.kley/my-lib"  (manual, link:)
```

## 5. Acceptance Criteria

- `kley add <pkg> --link` writes a `link:` specifier into `package.json`.
- `kley add <pkg>` (no flag) still writes `file:`.
- Existing `file:` setups keep working; documented in `README.md`.
