# f-47: `push --replace` / `--update`

- **Milestone:** M2
- **Complexity:** Low
- **Depends On:** None

## 1. Problem Statement

`publish --push` updates installations but offers no control to force a
replacement or to run the package manager's update for the pushed packages.
yalc provides `yalc push --replace` and `yalc push --update`.

## 2. Proposed Solution

Add two flags to `publish --push`:
- `--replace`: force replacement of package content in installations even if
  unchanged.
- `--update`: after pushing, run the package manager's update command
  (`npm/yarn/pnpm update <pkg>`) for each installation.

## 3. Implementation Plan

1. Add `--replace` and `--update` to the `Publish` variant in `src/main.rs`.
2. In the push loop (`src/commands/publish.rs`), honor `--replace` (skip the
   change check) and `--update` (invoke the PM update after `run_update`).
3. Without these flags behavior is unchanged.

## 4. Usage Examples

```bash
kley publish --push --replace
kley publish --push --update
```

## 5. Acceptance Criteria

- `--replace` forces content replacement in all installations.
- `--update` triggers the PM update command for pushed packages.
- Default push behavior unchanged.
- Documented in `README.md`.
